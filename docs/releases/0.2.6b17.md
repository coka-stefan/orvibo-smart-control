# v0.2.6b17

Fixes the MixPad LAN connection for accounts whose gateway does not accept the login email.

- **LAN login fallback**: Some MixPad gateways reject the account email or phone number at LAN login (`status=9`) but accept the account's cloud user ID. The integration now tries the configured username first and then the cloud user ID. Before this fix, these setups quietly ran cloud-only.
- **Consistent identity**: LAN control commands use the same identity the gateway accepted at login.
- **Separate LAN credentials unchanged**: If you configured separate MixPad LAN credentials, only those are used.

Update to **v0.2.6b17** in HACS and **restart Home Assistant**.

The full Python 3.12 offline suite passed, **801 tests with 1 skipped**, including new login fallback checks. Against a real MixPad Host S2, the gateway rejected the email, accepted the user ID, delivered live state pushes over LAN, and confirmed LAN light control (`status=0`).

This is published as an ordinary Release / Latest; `bN` distinguishes temporary diagnostic versions and does not mark the release as a Pre-release.
