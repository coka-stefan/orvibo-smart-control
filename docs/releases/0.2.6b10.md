# v0.2.6b10

Door-lock opening direction now follows four credential categories:

- **Opening from outside**: password (including temporary password), fingerprint, key, and card. Duress passwords, fingerprints, and cards belong to their corresponding categories.
- **Opening from inside**: other unlock methods, including face recognition and other/unknown methods, as well as a door-contact opening with no matching outside-opening credential from the four categories.
- Inside openings show “Person unknown” and no longer inherit the user or name from the previous outside opening. A door contact opening again, expiration, and duplicate pushes also cannot reuse the previous person.

This direction-inference strategy follows the user's request; it does not mean the firmware explicitly reported an inside opening. Event timing and identity numbers still need validation on real devices.

After updating to **v0.2.6b10** in HACS, **restart Home Assistant**. Continue entering names one per line under the integration option “Lock User Mapping” using `userID=name`, without brackets or commas; the user ID should match the lock's reported authorization number.
For multiple locks or the same number used by different credentials, use `deviceID/userID=name` or `deviceID/fingerprint/userID=name`. Existing mappings do not need to be entered again for this direction-rule update.

Snapshots continue to retain the 30 most recent images per lock by default; set 1–500 images in “Door Lock Snapshot Retention Count.”

The full Python 3.12 offline suite passed, 747 tests with 2 skipped. Real door-lock behavior still needs validation.

For details, see [Door Lock Direction, Unlocker Identity, and Snapshots](https://github.com/maycode0-0/orvibo-smart-control/blob/v0.2.6b10/docs/lock-opening-and-snapshots.md).

This is published as an ordinary Release / Latest; `bN` distinguishes temporary diagnostic versions.
