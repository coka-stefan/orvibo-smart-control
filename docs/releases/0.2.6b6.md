# v0.2.6b6

Fixed the recording card resource-loading entry point for the error “Custom element doesn't exist: orvibo-smart-control-nvr-card.” Storage mode now registers the dashboard JavaScript module resource automatically, updates older URLs, and refreshes the cache using the script-content hash. If registration fails for one card, it continues with the other; if the dashboard has not initialized yet, it retries after HA starts. The card script also supports repeated loading.

After updating in HACS, restart HA, force-refresh the browser with Ctrl+F5, then open the existing card configuration:

```yaml
type: custom:orvibo-smart-control-nvr-card
```

If it still does not appear, add `/orvibo_smart_control/www/orvibo-smart-control-nvr-card.js?v=0.2.6b6` under “Settings → Dashboards → Resources,” choose “JavaScript module,” then force-refresh. In YAML mode, add the module manually in resource configuration.

Validation includes resource registration and real HTTP file/MIME tests, card DOM tests, and a standalone headless Edge test that loads the module, registers the component, imports repeatedly, and displays the clip list after clicking search. Browser tests used simulated services and did not connect to the user's HA or a real NVR. Hard-drive search and playback still need device testing.

This is published as an ordinary Release / Latest; `bN` distinguishes development versions.
