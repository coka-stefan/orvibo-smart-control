# v0.2.6b9

Added inside/outside opening direction and unlocker attribution to door locks, and improved door-view snapshot storage:

- Credential-based unlocks using a password, fingerprint, key, or card count as opening from outside; an explicit inside opening does not inherit the previous outside user's identity.
- Supports new and old unlock events and administrator ID 0; duplicate, expired, and out-of-order old events do not overwrite the current opening attribution.
- Retains the 30 most recent snapshots per lock by default. The integration option “Door Lock Snapshot Retention Count” can be set to 1–500 images.
- Downloads snapshots immediately and retries with a newly signed URL on failure. Images captured in the same second are archived separately; a delayed old image does not replace the newest one. The latest image is restored after restart.
- The door-lock overview card shows recent opening details and updates with snapshots. It displays 30 images by default; set `history_limit` to change this. Automatic video cleanup protects retained snapshots.

After updating in HACS, **restart Home Assistant**. Open the integration's “Configure” menu to adjust “Door Lock Snapshot Retention Count” and “Lock User Mapping.” Name mappings support `7=John Doe` and `deviceID/7=John Doe`, and can be scoped to a credential type with `deviceID/fingerprint/7=John Doe`. If the card still shows old content, force-refresh the browser. If you previously added the card resource manually, update its URL to:

`/orvibo_smart_control/www/orvibo-smart-control-door-lock-card.js?v=0.2.6b9`

The full Python 3.12 offline suite passed, 744 tests with 2 skipped; no release-blocking issues were found in an independent pre-release review.
This implementation is based on static reverse-engineering evidence from HomeMate 5.2.6.307; **door direction, user identity, and real snapshots still need validation on a physical device**.
If firmware reports only a door-contact change and no explicit direction or user number, the corresponding information remains “unknown”; no inside-opening or person is inferred.
Names must be configured by the user. Names set through a service last only for the current run; use integration options to persist them.
Door-view snapshots depend on cloud events and image objects and do not include live door-view video.

For details, see [Door Lock Direction, Unlocker Identity, and Snapshots](../lock-opening-and-snapshots.md).

This is published as an ordinary Release / Latest; `bN` distinguishes temporary diagnostic versions.
