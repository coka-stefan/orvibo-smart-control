# v0.2.6b9

门锁增加内开、外开和开锁人归属，并优化猫眼抓拍保存：

- 密码、指纹、钥匙和卡片等凭据开锁判为外开；明确内开不会继承上次外开人员。
- 兼容新旧开锁事件、管理员编号 0；重复、过期和乱序旧事件不会覆盖当前开门归属。
- 每把锁默认保留最近 **30 张抓拍**，集成选项“门锁抓拍保留数量”可调整为 **1–500 张**。
- 抓拍立即下载，失败重新签名并重试；同秒多图分别归档，旧图迟到不覆盖新画面，重启恢复最新图片。
- 门锁总览卡片显示最近开门信息并随抓拍更新；默认展示 30 张，可通过 `history_limit` 调整。自动录像清理保护保留中的抓拍。

在 HACS 更新后**重启 Home Assistant**。进入集成“配置”，调整“门锁抓拍保留数量”及
“锁用户映射”。姓名映射兼容 `7=张三`、`deviceID/7=张三`，也可按凭据隔离：
`deviceID/fingerprint/7=张三`。卡片仍显示旧内容时强制刷新浏览器；此前手动添加卡片
资源时，可将原地址更新为：

`/orvibo_smart_control/www/orvibo-smart-control-door-lock-card.js?v=0.2.6b9`

Python 3.12 完整离线测试 744 项，跳过 2 项，整体通过；独立发布前审查未发现阻塞问题。
本轮依据 HomeMate 5.2.6.307 静态逆向证据实现，**门锁方向、人员和真实抓拍仍需实机验证**。
如果固件只上报门磁、没有明确方向或用户编号，对应信息保留为“未知”，不推测内开或人员。
姓名需自行配置；通过服务设置的姓名仅在当前运行有效，持久保存请使用集成选项。
猫眼抓拍依赖云端事件和图片对象，不含猫眼实时视频。

详细说明见 [门锁方向、开锁人及抓拍](../lock-opening-and-snapshots.md)。

本版按普通 Release / Latest 发布，bN 用于区分临时诊断版本。
