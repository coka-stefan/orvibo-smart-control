# v0.2.6b4

新增 Meari XTS/p2p=2 的实时 `camera` 实体：选中的录像机按实际在线通道创建摄像头，
从云端刷新授权，通过 P2P/中继持续收流，并用 HAOS 自带 FFmpeg 将 HEVC/H.264
转为 H.264，交给 HA 播放。无需另行部署视频服务。

在 HACS 更新并重启 HA 后，进入录像机设备页面，打开新增的“通道 1”“通道 3”等
摄像头实体。首次连接可能需要数十秒，缩略图首次超时可再次打开；诊断传感器本身
不会显示画面。通道列表改变后请重新加载集成。

修复慢速 P2P 建连与 HA 视频源超时的衔接，复用预连接和关键帧缩略图。断开、无帧、
取消、重载和 HA 关闭时回收协议与 FFmpeg 进程；未使用的预连接会自动释放。
原 `probe_video_stream` 继续用于有限首帧诊断，`decoded=false` 仍表示该动作不执行解码。

验证：Python3.12 完整离线测试647项通过，包含真实 FFmpeg HEVC→H.264 MPEG-TS→解码，
以及按10fps发送HEVC、用PyAV在流持续输出时解码多帧的测试。
用户已提供真实1号通道153,474字节HEVC关键帧；**真实连续画面及3号通道播放仍待用户验证**。

当前无声音，录像机硬盘历史检索、播放和定位尚未开放。只支持已通过动态库存、身份、
通道及默认hostKey校验的XTS设备，不能据此推断其他SDK或独立视频密码设备可用。

`bN` 后缀区分开发版本；GitHub 发布为普通 Release / Latest，**不是 Pre-release**。
详细用法见 [实时视频说明](https://github.com/maycode0-0/orvibo-smart-control/blob/main/docs/meari-live-video.md)。
