# v0.2.6b4

Added live `camera` entities for Meari XTS/p2p=2: selected NVRs create cameras for their actual online channels, refresh authorization from the cloud, receive a continuous stream over P2P/relay, and use HAOS's built-in FFmpeg to transcode HEVC/H.264 to H.264 for HA playback. No separate video service is needed.

After updating in HACS and restarting HA, open the NVR device page and select new camera entities such as “Channel 1” or “Channel 3.” The initial connection may take tens of seconds; if the first thumbnail times out, open it again. Diagnostic sensors do not display video. Reload the integration if the channel list changes.

Improved handling of slow P2P connections and HA video-source timeouts by reusing prepared connections and keyframe thumbnails. Protocol and FFmpeg processes are reclaimed on disconnect, no frames, cancellation, reload, or HA shutdown; unused prepared connections are released automatically.
The existing `probe_video_stream` remains available for limited first-frame diagnostics; `decoded=false` still means that action does not decode the frame.

Validation: the full Python 3.12 offline suite passed, 647 tests. This includes actual FFmpeg HEVC → H.264 MPEG-TS → decoding and tests that send HEVC at 10 fps and decode multiple frames with PyAV while the stream is active.
The user supplied a real 153,474-byte HEVC keyframe from channel 1; **real continuous video and channel 3 playback still need user validation**.

There is currently no audio; NVR hard-drive history search, playback, and seeking are not available. Only XTS devices that passed dynamic inventory, identity, channel, and default hostKey checks are supported; this does not establish support for other SDKs or devices with separate video passwords.

The `bN` suffix distinguishes development versions; GitHub publishes this as an ordinary Release / Latest, **not as a Pre-release**.
For details, see [Live Video Instructions](https://github.com/maycode0-0/orvibo-smart-control/blob/main/docs/meari-live-video.md).
