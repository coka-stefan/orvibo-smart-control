# v0.2.6b14

修复升级后卡片资源仍停留在旧版本，以及门锁猫眼抓拍无法加载的问题。

- **资源自动更新**：Home Assistant 启动完成后再次核对并原地更新卡片资源地址，避免启动期间延迟加载把地址恢复为旧版本；保留资源 ID 与卡片配置，静态注册首次失败也会重试。
- **抓拍可读取**：纠正图片解析接口的参数，新增集成独立的鉴权媒体源；现有 `config/media/orvibo_smart_control/` 图片与录像可直接读取，无需设置 `media_dirs` 或搬动文件。
- **录像服务**：`fetch_video` 返回值和已归档录像缓存统一使用新的媒体引用，保持与历史查询一致。

在 HACS 更新到 **v0.2.6b14**，**重启 Home Assistant 后强制刷新浏览器**。
已有仪表盘 JavaScript 资源条目、门锁卡片配置和本地抓拍可保留。
每把锁仍默认保留最近 **30 张**抓拍，集成选项可配置为 **1–500 张**；卡片的
`history_limit` 控制展示数量。

Python 3.12 完整离线测试 **787 项，跳过 2 项，整体通过**；覆盖启动资源地址回退、
注册失败重试、严格的 HA 媒体解析参数、已有抓拍目录映射、归档路径边界和缓存录像引用。
模拟 Home Assistant 的浏览器验证 **8 组通过，无浏览器错误**。
本地启动竞争复现和模拟验证不代替真机测试；实际升级后的资源更新、鉴权图片读取及云端
新抓拍仍需设备确认。用户原始诊断、截图和本地验证工具不包含在安装包中。

本版按普通 Release / Latest 发布，bN 用于区分临时诊断版本，不标记为 Pre-release。
