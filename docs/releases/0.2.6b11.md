# v0.2.6b11

Fixed door-lock battery and lock-state display.

- **Battery level**: Reads battery data from both the App property table and live pushes. Dry-cell and lithium battery sources are shown only when they have a valid reading; empty entries are hidden automatically and return when valid data arrives. Existing entity IDs and user-hidden settings remain unchanged.
- **Battery updates**: Partial pushes with missing or invalid battery data no longer clear the existing level; an explicit “not installed” marker clears that source. 0% is a valid battery level and is not confused with “unknown.”
- **Lock state**: Evaluates the main lock, door contact, and deadbolt separately, fixing the issue where “not deadbolted” appeared as “unlocked.” Partial cloud snapshots no longer discard the most recent lock state when fields are missing.

After updating to **v0.2.6b11** in HACS, **restart Home Assistant** and wait for cloud state to refresh.
For locks with five dry-cell batteries, valid dry-cell readings should display normally; the integration hides lithium battery entries with no valid data.
Battery level always uses the reported value and is never fixed to a percentage. Lock state should reflect the actual door contact, main lock, and deadbolt separately; a closed door alone does not imply the main lock is engaged.

The full Python 3.12 offline suite passed, **755 tests with 2 skipped**. It covers the property table, partial pushes, main-lock/deadbolt combinations, and entity hiding/restoration. Implemented based on static reverse engineering of HomeMate 5.2.6.307; battery and lock-state reporting on real devices still need confirmation.

Opening direction continues to follow the four-credential rule: password (including temporary password), fingerprint, key, or card counts as opening from outside; other methods and door-contact openings without a matching credential count as opening from inside. Door-view snapshot retention defaults to 30 images per lock and can be set to 1–500. See [Door Lock Direction, Unlocker Identity, and Snapshots](https://github.com/maycode0-0/orvibo-smart-control/blob/v0.2.6b11/docs/lock-opening-and-snapshots.md).

This is published as an ordinary Release / Latest; `bN` distinguishes temporary diagnostic versions and does not mark the release as a Pre-release.
