# v0.2.6b11

修复门锁电池电量和锁状态显示。

- **电池电量**：同时识别 App 属性表和实时推送中的电量。干电池、锂电池只显示有有效读数的来源；无值项自动隐藏，之后收到有效读数会恢复显示。用户手动隐藏的实体保持原设置，已有实体 ID 不变。
- **电量更新**：缺少电量或格式无效的局部推送不再清空已有电量；明确未安装时清空该来源。0% 仍属于有效电量，不会与“未知”混淆。
- **锁状态**：主锁、门磁和反锁分开判断，修复把“未反锁”当成“未上锁”的问题。云端局部快照不再因缺少字段丢失最近锁状态。

在 HACS 更新到 **v0.2.6b11** 后，**重启 Home Assistant**，等待云端状态刷新。
对于安装 5 号干电池的门锁，有效干电池读数应正常显示；没有有效数据的锂电池项由集成隐藏。
电量始终读取协议上报值，没有固定百分比。锁状态应分别反映实际门磁、主锁与反锁情况，
不会仅凭门已关闭就认定主锁已上锁。

Python 3.12 完整离线测试 **755 项，跳过 2 项，整体通过**。覆盖属性表、局部推送、
主锁与反锁组合，以及实体隐藏和恢复。依据 HomeMate 5.2.6.307 静态逆向实现，
实际设备中的电量和锁状态仍需确认。

开门方向继续采用四类凭据规则：密码（含临时密码）、指纹、钥匙、卡片为外开，其余方式
及未匹配到四类凭据的门磁开门判为内开。猫眼抓拍每把锁默认保留最近 30 张，可配置为
1–500 张。详情见[门锁方向、开锁人及抓拍](https://github.com/maycode0-0/orvibo-smart-control/blob/v0.2.6b11/docs/lock-opening-and-snapshots.md)。

本版按普通 Release / Latest 发布，bN 用于区分临时诊断版本，不标记为 Pre-release。
