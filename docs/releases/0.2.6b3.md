## 指定通道的视频连接与编码首帧测试

用户已在 v0.2.6b2 确认录像机云端返回 8 个通道，1、3 号的状态为 1 且 p2p 能力码为 2。
本版新增 `probe_video_stream`，实际尝试 MsgSvr、TURN、ICE、KCP 和指定通道的 VVP 实时请求。
它返回连接阶段、帧数、字节数和 H.264/HEVC 结构信息，不保存画面或凭据。

`v0.2.6b3` 按普通 GitHub Release 发布，设为 Latest，不标记 Pre-release。
在 HACS 更新或重新下载后重启 Home Assistant，执行：

```yaml
action: orvibo_smart_control.probe_video_stream
data:
  device_index: 2
  channel_id: 1
  timeout_seconds: 35
```

完成后再将 `channel_id` 改为 `3` 测试另一路，提供两次完整脱敏返回。
多个配置项时加 `entry_id`。设备序号对应最新设备列表；库存变化后需重新确认。

媒体进程在完成、超时、取消、集成卸载和 HA 关闭时停止并回收。
`encoded_video_verified=true` 仅表示识别到参数集与编码关键帧的基本结构；`decoded=false`，尚未通过解码器验证。
**此版仍不提供可直接观看的实时实体或录像机硬盘历史回放。**
没有独立视频密码时按 App 的默认 hostKey 模式尝试一次；失败不会自动尝试其他密码组合。
客户端 Android 版本后缀和参考发现协议版本的设备兼容性仍需这次真实测试确认。

Python 3.12 完整离线测试 592 项通过，覆盖协议封包、指定通道、模拟传输到首帧、慢速 TCP、无关 STUN 报文、进程硬超时和取消回收。
离线通过不能证明实际设备已可播放。详细字段见[诊断指南](https://github.com/maycode0-0/orvibo-smart-control/blob/v0.2.6b3/docs/nvr-video-diagnostics.md)。
