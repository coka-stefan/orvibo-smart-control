# v0.2.6b12

修复 5 号电池门锁电量仍显示未知的问题，并补齐全家诊断中的门锁数据。

- **干电池电量**：补充读取 `properties.battery_power`，覆盖 `deviceType=300`、`subDeviceType=400` 的旧式门锁。用户提供的库存和 6 次实时推送回放均读出 **60%**；电量随设备上报更新，不固定为 60%。
- **有效来源**：继续支持干电池、锂电池管理器；有效管理器读数与明确未安装标记优先。0% 是有效电量，缺少或无效的局部更新保留最近读数。没有有效数据的锂电池项自动隐藏，收到有效读数后恢复；保留现有实体 ID 和用户手动隐藏设置。
- **诊断导出**：全家诊断不再在第 50 台设备处截断，门锁增加库存与最新状态的属性及数值来源。逐设备保留内部大小限制，秘密和标识继续脱敏。

在 HACS 更新到 **v0.2.6b12**，然后 **重启 Home Assistant**，等待云端状态刷新。
这把锁的诊断回放为：**干电池 60%、门已关闭、主锁已上锁、未反锁**，没有锂电池读数。
回放验证了字段解析，升级后的真实 Home Assistant 实体显示仍需设备确认。

Python 3.12 完整离线测试 **769 项，跳过 2 项，整体通过**。新增旧式电量的库存、
周期合并、实时分发和实体显示回归，以及 86 台设备诊断与脱敏回归。独立审查未发现发布阻塞。
用户原始诊断文件不包含在仓库和安装包中。

开门方向继续采用四类凭据规则：密码（含临时密码）、指纹、钥匙、卡片为外开，其余方式
及未匹配到四类凭据的门磁开门判为内开。猫眼抓拍每把锁默认保留最近 30 张，可配置为
1–500 张。详情见[门锁方向、开锁人及抓拍](https://github.com/maycode0-0/orvibo-smart-control/blob/v0.2.6b12/docs/lock-opening-and-snapshots.md)。

本版按普通 Release / Latest 发布，bN 用于区分临时诊断版本，不标记为 Pre-release。
