# v0.2.6b12

Fixed unknown battery-level reporting on locks with five batteries and added more lock data to whole-home diagnostics.

- **Dry-cell battery level**: Reads `properties.battery_power` for older locks with `deviceType=300` and `subDeviceType=400`. The user's inventory and six live-push replays all reported **60%**; the level updates as reported by the device and is not fixed at 60%.
- **Valid sources**: Continues to support dry cells and the lithium-battery manager; a valid manager reading and an explicit “not installed” marker take precedence. 0% is a valid reading; missing or invalid partial updates preserve the most recent level. Lithium-battery entities without valid data are hidden automatically and return when valid data arrives; existing entity IDs and user-hidden settings are preserved.
- **Diagnostic export**: Whole-home diagnostics no longer truncate at 50 devices. Door locks now include inventory and latest-state properties and their value sources. Per-device size limits remain, and secrets and identifiers continue to be redacted.

Update to **v0.2.6b12** in HACS, then **restart Home Assistant** and wait for cloud state to refresh.
Diagnostic replay for this lock showed: **dry-cell battery 60%, door closed, main lock engaged, deadbolt not engaged**, with no lithium-battery reading.
The replay validates field parsing; the actual HA entity display after upgrade still needs device confirmation.

The full Python 3.12 offline suite passed, **769 tests with 2 skipped**. New coverage includes inventory, periodic merging, live dispatch, and entity display for legacy battery readings, plus diagnostics and redaction for 86 devices. Independent review found no release blockers.
The user's original diagnostic file is not included in the repository or installation package.

Opening direction continues to follow the four-credential rule: password (including temporary password), fingerprint, key, and card count as opening from outside; other methods and door-contact openings without a matching one of the four credentials count as opening from inside. Door-view snapshot retention defaults to 30 images per lock and can be set to 1–500. See [Door Lock Direction, Unlocker Identity, and Snapshots](https://github.com/maycode0-0/orvibo-smart-control/blob/v0.2.6b12/docs/lock-opening-and-snapshots.md).

This is published as an ordinary Release / Latest; `bN` distinguishes temporary diagnostic versions and does not mark the release as a Pre-release.
