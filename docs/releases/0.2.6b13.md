# v0.2.6b13

Improved the door-lock card so the current lock state, most recent opening, and door-view snapshots are easier to review.

- **Lock state**: Shows the main lock, door contact, and deadbolt separately, using distinct indicators for locked, unlocked, abnormal, and unknown states. At the top, it shows a battery reading from a source with a valid percentage; 0% is valid.
- **Recent opening**: Highlights the person, inside/outside direction, method, and time. Inside openings do not show the name or credential type from the previous outside opening.
- **Door-view snapshots**: Previews the newest image separately and lets users scroll horizontally through older thumbnails. Click to open a large view; use previous/next, arrow keys, and Escape. Closing restores focus to the image.
- **Failure recovery**: Resolves up to four snapshot URLs concurrently while preserving their order. Failed refreshes retain existing images; a failed single-image lookup reuses that image's existing URL. Results from old requests are discarded after changing the device configuration.
- **Form input and actions**: Unrelated state updates do not rebuild the card. Relevant refreshes preserve entered text, focus, cursor, and image scroll position. Expandable sections support keyboard interaction; the card adapts to narrow phone columns, light/dark themes, and reduced-motion settings.

Update to **v0.2.6b13** in HACS, **restart Home Assistant, then force-refresh the browser** to clear the old card-script cache.
Existing door-lock overview cards and standalone temporary-password card configurations continue to work.

Each lock still retains the 30 most recent snapshots by default. Set **1–500** in the integration option “Door Lock Snapshot Retention Count.” The card's `history_limit` controls its display count; the integration option controls disk retention.
Opening direction remains based on four credential types: password (including temporary password), fingerprint, key, and card mean outside; all other methods and door-contact openings without a matching credential mean inside.
See [Door Lock Direction, Unlocker Identity, and Snapshots](https://github.com/maycode0-0/orvibo-smart-control/blob/v0.2.6b13/docs/lock-opening-and-snapshots.md).

The full Python 3.12 offline suite passed, **775 tests with 2 skipped**, including new battery, inside-opening identity, image concurrency, failure retention, and stale-request isolation tests.
Simulated Home Assistant browser checks passed **8 groups with no browser errors**. They covered 320/375/768/1024/1440px layouts, action buttons at least 44px, input and focus retention, large-image keyboard actions, image failure recovery, empty galleries, and the standalone password card.
Simulation does not replace real-device validation; the actual HA theme, mobile display, cloud snapshots, and temporary-password action still need device confirmation.
